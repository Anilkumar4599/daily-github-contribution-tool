\### Project Name



AI Learning and Technical Skills Development Journey

27 September 2026



\### Project Purpose

Inventory, Power BI, AWS, Git/GitHub, AI-assisted work, and DevOps.

6\. What Did Not Go as Planned

6.1 Documentation Was Sometimes Ahead of Practical Work



Some AWS and DevOps activities were documented without corresponding

hands-on implementation.



Lesson



Documentation should not be treated as evidence of practical experience.



Future records should clearly distinguish:



Documented

Practiced

Tested

Implemented

6.2 Practical Learning Needs Dedicated Time



Technical tools such as Power BI, AWS, and DevOps require hands-on practice.



Lesson



A regular practical schedule should be maintained alongside daily

documentation.



6.3 Automation Should Come After Process Understanding



It is tempting to automate a repetitive task immediately.



Lesson



The better sequence is:



Understand Process

&#x20;     ↓

Document Process

&#x20;     ↓

Identify Problems

&#x20;     ↓

Improve Process

&#x20;     ↓

Validate Process

&#x20;     ↓

Automate

7\. Key Lessons Learned

Lesson 1 — Start Small



A small working exercise is easier to understand and troubleshoot than

a large project.



Lesson 2 — Validate Data



Analysis should begin only after checking the quality of the input data.



Lesson 3 — Record Assumptions



When information is missing, the assumption should be documented rather

than silently inferred.



Lesson 4 — Test the Result



A completed document or automation idea should have simple test cases

where applicable.



Lesson 5 — Separate Theory and Practice



Learning a concept and implementing the concept are different achievements.



Lesson 6 — Keep Evidence



Screenshots, test results, Git commits, reports, and actual outputs can

help demonstrate what was completed.



Lesson 7 — Improve Continuously



Each project iteration should identify at least one improvement for the

next iteration.

13\. Final Retrospective



The project has established a consistent foundation for technical learning

and documentation.



The main opportunity for the next stage is to increase the percentage of

learning activities that involve actual hands-on practice.



The overall learning approach can therefore evolve from:



Learn → Document



to:



Learn → Document → Practice → Test → Measure → Improve



This approach should help convert theoretical knowledge into practical

skills while maintaining a clear record of progress.

Conclusion



This retrospective provides a checkpoint for the project.



The key lesson is that consistent learning is valuable, but the strongest

progress comes when learning is converted into practical work, tested,

measured, and improved.
