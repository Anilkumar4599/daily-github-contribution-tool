# Day 112 — QC Defect Analysis Prompts

## Project Overview

This project contains 10 reusable AI prompts for analysing QC defects in ATM E-Surveillance systems.

## Objectives

- Classify defect severity.
- Identify HW, SW, EDGE, and joint ownership.
- Find show-stopper defects.
- Validate defect-tracker data.
- Analyse recurring defects.
- Support root-cause analysis.
- Assess intermittent failures and defect ageing.
- Prepare corrective-action plans and management reports.

## Project Files

- `QC_Defect_Analysis_Prompts.md` — Prompt library, input-validation rules, sample dataset, and success criteria.
- `README.md` — Project overview and usage instructions.

## How to Use

1. Open `QC_Defect_Analysis_Prompts.md`.
2. Select the prompt matching your QC task.
3. Supply the relevant defect-tracker data.
4. Validate missing or incorrect fields before interpreting results.
5. Review AI findings against logs, screenshots, test results, and engineering evidence.
6. Record approved actions in the official QC tracker.

## Validation Checklist

- [ ] All 10 prompts are present.
- [ ] Input-validation rules are documented.
- [ ] Missing information is reported rather than invented.
- [ ] The sample dataset is labelled fictional.
- [ ] Failure-rate calculations require valid trial counts.
- [ ] Root causes are not claimed without supporting evidence.
- [ ] Management recommendations distinguish facts from assumptions.

## Limitations

AI-generated analysis is decision support only. Engineering teams must verify technical findings and approve corrective actions and defect closure.
