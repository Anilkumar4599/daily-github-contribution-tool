\# Contributing Guidelines



Thank you for your interest in contributing to the Daily GitHub Contribution Tool!



This repository is used to document daily learning activities, practical exercises, Python automation, Git and GitHub learning, AI learning, procurement automation and quality-control projects.



These guidelines explain how to contribute in a simple and organized way.



\## 1. Getting Started



1\. Clone the repository or download the project.

2\. Open the project folder.

3\. Review the existing folder structure.

4\. Read the README.md file before making changes.



Repository:



https://github.com/Anilkumar4599/daily-github-contribution-tool



\## 2. Branching Guidelines



Create a separate branch before starting new work.



Examples:



\- `feature/new-documentation`

\- `feature/python-automation`

\- `bugfix/fix-validation`

\- `docs/update-readme`



Avoid making unrelated changes directly on the main branch.



\## 3. File and Folder Organization



Keep new work inside the relevant project folder.



Examples:



\- `Git/` – Git and GitHub learning.

\- `Python/` – Python exercises and automation.

\- `AI/` – AI learning and prompt documentation.

\- `Procurement/` – Procurement-related automation and analysis.

\- `QC/` – Quality-control projects.



Use clear and meaningful file names.



\## 4. Coding and Documentation Guidelines



\- Keep implementations simple and understandable.

\- Use meaningful file and variable names.

\- Add comments when they help explain the logic.

\- Include a README.md for new projects where appropriate.

\- Document examples and expected results.

\- Avoid unnecessary changes to unrelated files.



\## 5. Testing Guidelines



Before submitting changes:



1\. Run the relevant Python script or validation command.

2\. Execute available unit tests.

3\. Review the updated documentation.

4\. Check the Git working tree using `git status`.

5\. Review staged changes before committing.



Example Python test command:



`python -m unittest -v`



\## 6. Commit Message Guidelines



Use clear commit messages that explain the work.



Examples:



\- `Add Python input validation`

\- `Update Git learning documentation`

\- `Fix CSV report generation`

\- `Add procurement automation example`



Avoid unclear messages such as `update`, `changes` or `test`.



\## 7. Pull Request Guidelines



When contributing through GitHub:



1\. Create a feature branch.

2\. Complete your changes.

3\. Test the implementation.

4\. Commit your changes.

5\. Push your branch to GitHub.

6\. Open a Pull Request against the main branch.

7\. Explain what changed and how it was tested.



\## 8. Important Rules



\- Keep contributions relevant to the project.

\- Do not upload passwords, access tokens or confidential information.

\- Do not delete existing project files without a valid reason.

\- Avoid committing temporary files and Python cache folders.

\- Keep documentation accurate and easy to understand.



\## 9. Questions and Suggestions



For questions, improvements or suggestions, please use the GitHub Issues section of the repository.



Thank you for helping improve this learning and automation repository!
